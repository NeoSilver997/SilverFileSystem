# Face Matching Review Flow — How It Works

## Overview
Faces detected in photos are **NOT directly assigned** to named groups. Instead, they go through a **Review flow** where the user confirms or rejects each match before it's final-linked.

## The Flow

```
Photo Scan → Face Detection → InsightFace Embedding → Match Against Named Groups → Review Tab → User Confirm/Reject → Final Link
```

### Step 1: Photo Scan (`bin/cli.js face-scan`)
- Scans unscanned photos from the database
- For each photo, runs InsightFace to detect faces and compute 512-dim embeddings
- Stores face records in `detected_faces` table

### Step 2: Match Against Named Groups (`lib/face-detector.js`)
- Loads named groups with their master + secondary reference embeddings
- For each new face, computes **cosine similarity** against all group samples
- If similarity > **0.75** threshold → sets `suggested_group_id` (NOT `face_group_id`)
- Sets `match_source='auto'`, `match_confidence=<score>`, `match_reviewed=0`
- **Face is NOT in any group yet** — only has a suggestion

### Step 3: Review Tab (`/faces` → Review)
- Shows all faces with `match_reviewed=0` and `suggested_group_id IS NOT NULL`
- Groups faces by their suggested target group
- Shows confidence score (cosine similarity)
- User can:
  - **Confirm** → moves `suggested_group_id` → `face_group_id` (final link)
  - **Reject** → clears suggestion, face stays ungrouped
  - **Reassign** → move to different group

### Step 4: Final Link
- Only confirmed faces have `face_group_id` set
- These appear in the named group's face list

## Database Schema

```
detected_faces:
  face_group_id        — NULL until confirmed (final link)
  suggested_group_id   — Set during scan (pending review)
  match_source         — 'auto' (scan) or 'manual' (user)
  match_confidence     — Cosine similarity score (0-1)
  match_reviewed       — 0 = pending, 1 = reviewed
```

## Key Rules
1. **Never skip review** — scan always sets `suggested_group_id`, never `face_group_id`
2. **Ignored faces skipped** — faces marked as ignored (unknown/friend/non-face) are excluded from matching
3. **Threshold 0.75** — only strong matches (cosine similarity > 75%) are suggested
4. **Gender penalty** — mismatched gender applies -0.15 penalty to score
5. **All samples must have embeddings** — phash-only matching is not used (caused false positives)

## Files Involved
- `bin/cli.js` — face-scan command, sets `suggested_group_id`
- `scripts/scan_all.js` — batch scan, same logic
- `lib/face-detector.js` — `findMatchingGroup()` with cosine similarity
- `lib/database.js` — migration v15 adds `suggested_group_id` column
- `server.js` — Review API endpoints (`/api/faces/review/*`)
- `public/faces.html` — Review tab UI with confirm/reject/reassign

## Verification
1. Run `node bin/cli.js face-scan --limit 500` — new faces detected
2. Check `SELECT COUNT(*) FROM detected_faces WHERE suggested_group_id IS NOT NULL AND match_reviewed = 0` — should show pending count
3. Open `/faces` → Review tab — faces grouped by target person
4. Confirm/reject — check `face_group_id` is set only for confirmed faces
